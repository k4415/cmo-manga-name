# 4列出力と保存

最終更新: 2026-09-14

## セルの契約

|列|内容|
|---|---|
|A 画像サイズ|縦長／正方形／横長。比率文字列ではない|
|B 登場人物|画像に描く人物の確定名。複数は「・」区切り。人物なしは空欄|
|C セリフ等|読者に見せる文字。1要素1行。無言は空欄|
|D コマ内容|場面・人物・構図・演出・文字等の必要な項目を、項目ごとに改行した短い絵の指示。詳しくはdirection-and-review.md|

1データ行=生成画像1枚。画像番号・秒数・出典ID・評価・状態を追加しない。画像内に複数コマを持てる。D列は絵の指示であり、アプリ設定の機械コマンドではない。

C列は `名前「本文」`、`名前（本文）`、`NA：本文`、`SE：本文`、`注釈：本文`。NA・SE・注釈の本文を「で始めない。取込側が `NA「本文」` 形式と解釈して先頭の「と末尾の」を除去し、本文が欠けることがある。引用や強調で括弧が必要なら『』を使う。発話名は設計の確定名と一致させる。確認済み取込仕様の話者名は20文字以内（UTF-16の単位）。長い名前は無断省略せず、短い確定名を相談する。話者が画像外にいる場合は、B列へ無理に足さず演出を明示し、補助データの `offscreen_speakers` に記録する。

画面内文字もC列のNA等で定義し、D列で「C列3行目を端末画面内に配置、ナレーション枠にしない」等と指定する。この例外は生成結果で確認する。C列本文全体をD列に二重記載しない。強調対象の短い語だけは引用できる。

チャット・資料・グラフ・看板等も、読者に読ませる文字はC列へ定義する。定義しない部分はD列で無文字の枠・罫線・記号として指定し、説明文、メッセージ、数値、割合を補わせない。正式素材に含まれるロゴ等の文字はその素材を正本にし、C列で同じ文字を別表示させない。原稿文字と素材内文字の配置先を分けて照合する。原画像をそのまま掲載するブロックは生成用4列の対象外とする。

複数コマはD列にコマ数・区画・読順と文字行の割当を記す。本文の※と注釈本文先頭の同じ印を対応させる（例: 本文の※1に対して `注釈：※1 補足内容`）。番号は0〜3桁、全半角を正規化して照合する。印の直後に本文の数値が続く場合は区切りを入れて番号を曖昧にしない。注釈を付けても未確認の主張は事実にならない。作例表示等の単独注釈は印を付けず、空の対応先として扱える。

実入力タブを読める場合はその完全な見出しを保持する。標準C見出しは改行を含む:

```text
セリフ「」　
心の声（）　
ナレーションNA：
効果音SE：　
注釈 ：（本文の印は語の直前に ※ ）
```

## ローカル成果物

- `storyboard.json`: 4列セルと機械確認用の管理情報。JSONが文字とセルの正本。
- `storyboard.tsv`: 見出し付き4列。改行セルを引用符で囲み、内部引用符を二重化。
- `characters.md` / `characters.json`: 人物設計と生成用指示文。
- `production-notes.md`: 場面ID・画像番号・内部コマ数・配置理由・未確認事項。動画はカット秒数と読み上げを含む。

### 参考素材と原画像の対応

演出設計時に、ロゴ・商品・パッケージ・実画面・実例等の必要性を確認する。既存の案件素材から探し、見つからない場合は「必要な画像／使用箇所／必要な理由」をまとめて伝える。欠けた素材が不可欠な画像だけを保留し、独立して作れる脚本や場面は進める。素材を必要としない作品に収集作業を強制しない。

使用する素材は制作メモで次の項目を対応させる。必要になったものだけ記録し、取込用4列へ管理列を追加しない。

|項目|内容|
|---|---|
|素材と参照先|判別できる名前、出典・利用可否、実在するファイルまたは素材ID。期限付き署名URLは保存しない|
|使用箇所|生成画像・内部コマ・画面内の位置、または記事内の掲載ブロック|
|扱い|外見を正確に保つ／構造を参考にする／原画像をそのまま掲載する|
|保持・変更|形・配色・文字等の保持対象と、構図に合わせる部分。画面内の別人物・別作品の文章を転写しない指定|
|確認範囲|この素材から分かること、分からないこと、不足・未確認の条件|

正確な外見が必要な素材を、雰囲気だけの参照として扱わない。実画面の配置を参考にする時は、そこに写る別の人物・文章を本作へ持ち込まない。本人の顔や正式な文字まで再現する必要がある場面は、利用できる該当素材を確認する。第三者の広告・漫画の画像は構成研究と生成参照を区別し、権利リスクのある画像を生成へ渡さない。

実際の制作物等を原画像で掲載する混在記事では、生成画像と原画像・本文・図解の掲載順を制作メモへ記す。原画像を再生成して実例と呼ばない。実物の存在、品質評価、所要時間、成果は別の確認事項。注釈を付けても未確認の主張を事実として扱わない。

引き渡し時は、各素材の使用箇所・扱い・保持条件がD列や実際の参照設定に反映されているか確認する。素材が保存されているだけで生成へ渡ったとは扱わない。MCPに参照設定がなければ認可済みUIか手動設定メモで引き継ぎ、未設定を明記する。

演出設計時の主役・距離・角度と前後の差は制作メモへ保持し、取込表に列を増やさない。取込やMCPの実行も依頼された場合、現行の入力スキーマが構図・角度を受け付けるなら、D列と整合する選択値へ対応させる。設計済みなのに一律「おまかせ」へ落とさない。細かな切り取りはD列に残し、未対応の列やAPI項目は創作しない。

これらは作品ごとの新規フォルダへ出し、既存成果物を無断上書きしない。更新依頼では版を分ける。画像数はデータ行数、シート行は見出し1行なら画像番号+1。抜粋は全編番号・今回行・保存先行を別に持つ。

### storyboard.json

必須: `media`=`article` / `short_video` / `other`、`characters`=全確定名の文字列配列、`rows`=4文字列の行配列、`panels`=rowsと同数の管理配列。各panels要素は `count`=内部コマ数、`text_map`=各コマへ割当てるC列の1始まり行番号配列。例: `{"count":2,"text_map":[[1,2],[3]]}` は上から2コマに文字を分ける。無言の1コマは `{"count":1,"text_map":[[]]}`。

任意: `header`=実見出し4文字列。画像外話者は該当panels要素の `offscreen_speakers` 配列。注釈がある画像は `annotation_map` を同要素へ追加し、各要素を `{"note_line":3,"target_lines":[1]}` とする。単独の作例表示は `target_lines:[]` とし、内容の妥当性を人が確認する。

動画は `duration_seconds` と `cuts` を両方持たせる。cutsの各要素は `image`=1始まり画像番号、`start`、`end`=秒数。読み上げ・編集指示は任意の `voice`、`note` に記録できる。カットは0から全尺まで連続、時間順に並べる。ディゾルブ等もタイムライン上の区間を二重計上しない。画像を複数カットで使う場合は同じ番号を参照する。

補助ツールは標準ライブラリのみのPython 3で実行:

```text
python3 <このスキルの場所>/scripts/storyboard.py <作品>/storyboard.json --output <作品>/storyboard.tsv
python3 <このスキルの場所>/scripts/storyboard.py <作品>/storyboard.json --compare-cells <読戻しセル配列.json>
```

検証は行列、サイズ、人物名、文字記法、内部コマへの文字割当、注釈対応、秒数連続性、TSV往復を確認する。絵の指示の意味、事実の正しさ、面白さ、可読性を判定したものではない。Pythonなしでも制作できる。別の既存ツールでセルを保ったファイルを出し、未実行の検証を明記する。

## 利用者のシートへ保存

1. 利用者指定ブックの名前・URL・タブ一覧・編集可否・実入力タブを確認。固定の原本IDへ書き込まない。
2. 最終4列と新規タブ名、保存先を提示。既知の承認・依頼を引き継ぐ。同じブックのテンプレートを複製し、新規作品タブへ書く。テンプレートタブがなければ標準4列の新規タブ案を提示し、その内容で保存依頼を受けて作成する。既存の原稿・原本タブは保持する。
3. 複製した例文等が作品の末尾に残らないよう、新規タブの入力領域を整理する。行数・折返し・行高を新規タブ内で調整。列E等の参考画像を取込範囲に含めない。
4. APIではRAW等で文字列として入力。ブラウザでcmd+v等の貼付をする場合は、貼付の直前にクリップボードへ正本を再ロードして先頭を確認する。並行作業で別の内容に置き換わっていることがあり、そのまま貼ると関係ない文が入力範囲へ入る。貼付後は全セル照合し、不一致なら即座に正本を貼り直す。ブラウザは改行・引用符・先頭記号の数式化を確認。セルを書いた後、新規タブのA:Dの全使用範囲を、見出しを含む二次元配列で読み戻し、`--compare-cells` で正本と照合する。末尾の空行と各行末の空欄省略だけは補正され、最終データ行より後の旧原稿は不一致になる。コピー範囲だけを取得した場合、末尾の残存確認は未完了とする。取得時は表示値だけでなく、可能なら数式でないことも確認する。
5. 表示も確認し、タブ名・URL・画像数・コピー範囲 `A1:D(画像数+1)` を報告する。読戻し不可は保存検証未完了とする。読戻しはA:Dの二次元配列を取得できれば手段を問わない。セル配列をファイルへ落とせない環境では、取得した二次元配列のJSONのハッシュを正本側の同じ形のハッシュと比較して一致を確認し、不一致時はセル単位のハッシュで位置を特定する。

接続は既存の認可済み連携・ブラウザを使う。接続なし・閲覧のみでも制作を続け、TSVを渡す。Google SheetsへのTSVインポート時はタブ区切り・文字列扱いで新規タブへ。ローカルファイルの確認と外部保存を区別する。利用者へ公開設定や過大な権限を要求しない。XLSXが必要なら利用可能な表計算ツールで同じセル配列から作り、文字列型と改行を確認する。

AIが新規に作るD列は「場面：」「人物：」「構図：」「段構成：」等の項目名から始め、先頭を `= + - @` にしない。ブラウザ貼付やファイル取込で数式化の懸念がある先頭 `= + - @` 等を検出した場合、ユーザーの原文を勝手に変えずRAW入力か文字列型XLSXで受け渡す。検証ツールのエラーを無視してTSVを配布しない。

再実行時はタブ作成・入力の状態を先に照合。成功不明で新たなタブを増やさない。他者の変更があれば差分を示し、上書きしない。古い5列版は列の対応を確認できる場合だけ外部保存用へ変換し、CMO取込用の4列も保持する。未知の列構成は確認する。

最後に、CMO AI Proへの貼付はコマ登録・プレビュー・人物照合の工程であることを案内する。貼付だけで画像生成・完成動画まで終わったとは報告しない。

## 任意の発声プランと検証

動画で読む文字と画像の切替を照合する場合、正本JSONへ `audio_plan` を付ける。audio_planを付けるだけなら4列のセルは変更しない。`cuts`は表示時間の正本、C列は文字の正本、発声プランは読むC列行の参照と順序を保持する。旧 `cuts.voice` / `speech_groups` は互換のため読み込みを妨げないが、この検証では自動解釈しない。新規制作・依頼された改訂で併記する場合、発声の正本はaudio_planとし、旧補助データとの不一致を制作メモへ示して整合させる。今回のスキル更新だけで既存作品を変更したり旧フィールドを削除したりしない。

- `version`: 整数1。
- `segments`: 読む順の配列。各要素は `cut`（cutsの1始まり番号）、`line`（その画像のC列内の1始まり行番号）。任意の `group` は一続きの発言のID。
- `groups`: 任意配列。各要素は重複のない `id`、`speaker`（確定人物名またはNA）、`body`（そのグループの発声本文を順に連結した文字列）。話者名や括弧を本文へ含めない。

同じグループの音声は画面が切り替わっても自然につなげ、カットごとに言い直したり均一な間を挟んだりしない。別話者や無音カットを挟む場合は別グループにする。同じ画像の複数話者は、それぞれのC列行を読む順に指定する。新規制作・依頼された改訂で一つのC列行の途中に無音や別話者を挟む必要があれば、文言を保持してC列の要素を分け、吹き出し構成への影響を提示する。既存作品へ発声情報を付けるだけの操作でセルを再編しない。

この形式では、音声をつなぐ各カットのC列にも、その時読む文字を置く。聞き手だけの画には画外話者の吹き出しとして定義し、必要ならoffscreen_speakersも指定する。文字なし画像へ別画像の台詞を重ねる方式はこの参照形式では未対応。

SE・注釈は発声に指定しない。読まない画面文字はsegmentsから外す。無音カットは対応segmentなし、全編無音を明示する場合は空配列。audio_planそのものがない旧データは「発声未指定」であり0文字とは報告しない。C列の未参照行は非発声として扱うため、意図しない読み忘れの意味判断は制作時に行う。

audio_planは動画編集メモを伴う形式なのでcutsが必須。通常の記事には付けない。付けた場合はTSV書出し時も整合検証し、不正な任意プランを黙って無視しない。

同じcut/lineの二重指定、逆順のカット、未定義グループ、話者やグループ本文の欠落・重複を検出する。カット内の読み順はsegmentsの指定順。別カットで同じ画像・行を再度読む指定は有効で、全体発声量には毎回数える。画像ごとの文字量では同じ行を一度だけ数える。文字数40超や発声本文400からの差はエラーにも自動分割にも使わない。

```text
python3 <スキル>/scripts/storyboard.py <作品>/storyboard.json --speech-report <作品>/speech-report.json
```

レポートは全体・カット別・画像別の文字数、発声本文、発声グループ数を返す。旧発声フィールドとの併記はlegacy_fields_presentと注記で知らせる。空白・Unicode句読点・注釈参照印を除外した表記文字数と、句読点込みの本文量を分ける。既存ファイルは上書きせず、新しい出力先を使う。音声生成・尺の実測・外部保存は実行しない。
