# CMO AI Proへのキャラクター引き継ぎ

最終更新: 2026-09-14

ネームと設計の完成後、ユーザーがキャラクター画像生成を依頼した時だけ実行する。既知の対象・人物・設計を再承認させない。ネーム相談中の「キャラを作って」が設計と実画像生成のどちらか文脈から判別できない場合は、まず設計提案として扱い、有料の実生成へ拡張しない。生成を依頼済みの文脈なら同じ確認を繰り返さない。MCPがなくても人物ごとの生成用指示文を納品できる。

## 実行順序

1. 接続先が提供するツール一覧・入力スキーマを読む。以下は確認済み契約の手引きであり、接続先の現行スキーマを優先する。ツールが公開されていない場合、名前を創作して呼ばない。
2. `list_projects`、`list_manga_works`、`get_manga_work` 等でユーザーの案件・作品・既存人物を確認する。実IDは返却値を使う。名前一致だけで別案件を同一視しない。
3. 作品が必要なら対象案件・作品名とユーザーが選択したスタイルを確定する。新規作品で生成することが既に依頼され、これらが確定していれば再承認を求めない。既存作品への生成だけが指定された場合や、新規作成の必要性が未提示なら、作成予定の対象を示して必要な判断を受ける。スタイル選択だけを作品作成依頼へ読み替えない。`create_manga_work(project_id,title,style_id)` の返却 `nameSetId` と `workId` を別々に記録。未選択なら `list_manga_styles` 等の実在候補から選んでもらい、勝手に画風を確定しない。
4. 設計版・人物・対象と依頼キーをローカルの生成状態ファイルへ記録してから、人物ごとに `start_manga_character_generation` を呼ぶ。通常は依頼された各人物1件から。画面に登場しない声だけの人物は自動で生成対象に加えない。余分な候補の課金生成を追加しない。
5. `characterId`、`jobId`、`status`、`reused` を記録。`get_job_status` と `get_manga_work` で完了と対象作品への割当を確認する。待機は上限を設け、長引けば現在の状態と再開方法を伝える。
6. 生成画像をユーザーへ提示し、設計との一致・人物の識別を確認してもらう。受理・生成完了・自動割当・人間の採用は別。確定名と実IDの対応を保存する。

## 生成の入力

|項目|内容|
|---|---|
|project_id|実案件ID|
|name_set_id|生成対象の実nameSetId。workIdとは別|
|name|設計の確定名。確認時上限100文字|
|gender / age / role|任意。確認時上限50 / 50 / 100文字|
|instructions|設計した生成用指示文。確認時1〜4,000文字|
|idempotency_key|同じ依頼・再試行で維持。確認時1〜128文字|

入力が上限を超えたら意味を保持して整理し、設計の変更点を示す。不要な空の任意項目は送らない。状態ファイルには設計版・対象ID・確定名・依頼キー・返却ID・状態・確認日時を記録し、APIキー・認証情報・署名URLは保存しない。

## 中断と再試行

通信失敗で結果不明なら、状態ファイルとジョブ・作品を先に照合する。成功不明の依頼を別キーで再送しない。同じ内容とキーでの安全な再試行が接続先で可能な場合のみ行う。一部成功は成功人物のIDを保持し、失敗分だけ扱う。権限・上限・スキーマ不一致等が解決できなければ未実行範囲と手動用指示を渡す。

キャラクター生成のみの依頼からネームのMCP取込、コマ画像生成、採用、公開へ範囲を広げない。作画も依頼されていれば、その範囲の現行機能と対象を確認し [generation-review.md](generation-review.md) へ進む。

## MCPなし

CMO AI Proで対象作品と作画スタイルを選び、人物ごとの名前・属性・生成用指示文を入力して生成する案内を渡す。キャラクター画像を確認後、4列を貼り付けて人物を照合する。画面の現行操作は必要な場合に確認し、未確認のボタン名を断定しない。

認可済みブラウザで代行する場合の画面の流れ（確認時点の表示。ボタン名は変わりうるので見えている表示で確認する）:

1. 案件を開き「漫画制作」へ。01プロジェクトで新規作成し、プロジェクト名と作画スタイルを選ぶ。作画スタイルは作成後に変更できないので、ユーザー指定を先に確定する。
2. 02キャラクターデザインで人物を追加する。入力は名前・役割・性別・年齢・キャラクター指示文で、髪型・服装・全体の参考画像は任意。1人ずつ生成し、クレジット残高の差で単価を記録する。生成完了後にキャラシートを開き、髪型・衣装・識別点を設計と照合する。
3. 03コマ生成の「スプレッドシートから貼り付け」に見出し付きの4列を貼り、プレビューで人物の自動紐づけ・文字種別・サイズを確認してから取り込む。取込後は各コマの種別・話者・本文・コマ内容を読み戻して原稿と照合し、差分があればコマ単位で修正して保存する。
4. コマ画像の一括生成は有料の別工程として、依頼範囲に含まれる場合だけ進める。

実IDは画面やキャラシートのパスから取得し、状態ファイルへ記録する。署名付きURLは保存しない。
