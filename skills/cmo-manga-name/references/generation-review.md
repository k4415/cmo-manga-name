# コマ作画の引き渡しと実画像確認

最終更新: 2026-10-07

ユーザーがコマ作画・画像修正・漫画完成まで依頼した場合に読む。ネーム制作のみでは実行しない。既知の対象・承認済み原稿・依頼範囲を引き継ぐ。公開や広告配信は別の依頼範囲として扱う。

## 生成前

接続先の現行ツールと入力スキーマを確認し、対象作品・作画スタイル・人物・既存コマの状態を読む。未公開のツール名や実IDを作らない。承認済み原稿のサイズ・文字・人物・コマ割り・構図を対応させ、登録後に読み戻して照合する。取込側の記法解釈（NA・SEの本文先頭の「など）で本文が欠けることがあるので、文字要素は本文まで照合する。複数内部コマの画角が異なる場合は各区画のD列指定を保持し、一つの設定値で上書きしない。

[output-and-save.md](output-and-save.md) の素材対応に従い、使用箇所ごとの参照設定を確認する。短いD列で場所・動作・対象が分かり、共通設定・参考画像が実際に生成側へ渡ることを確認する。ネーム段階のレビュー記録と未解決事項を引き継ぎ、脚本・D列・構図や角度の選択値・参照の食い違いを解消する。通常の局所修正で全編3周をやり直す必要はない。

依頼キー・登録済みID・ジョブ・生成版・選択状態を作品の制作記録へ残す。通信エラーやタイムアウトで成功不明なら状態を照会してから再開し、登録・生成を重複実行しない。失敗・上限到達は既存成功分を保持し、必要な対象だけを再試行する。画面の操作がない機能は手動用指示として渡す。

## 実画像を確認する

全編を実際の掲載順と想定表示幅で確認したあと、1画像ずつ長辺1000px以上で確認する。縮小一覧だけでは手の本数や端末の向きを見落とす。文字やロゴ等の細部は必要な箇所を拡大する。少数の成功画像や生成成功ステータスだけで全編確認済みにしない。

- 文字: 原稿の欠落・追加・重複・誤字、話者としっぽ、注釈の可読性。読み順はC列の行順どおりに読めるか（縦長・正方形は右上→左上→右下→左下）を実画像で確かめる。画面の小文字や数値も確認する。
- 同一性と連続性: 人物、商品、場所、小道具、所持する手、通話や作例内の人物。前後の画像と照合する。服装・時間帯・左右の配置も前後で照合する。
- 人体: 人物ごとの腕・手・指の数と関節の向き。2人が触れ合う画像、手前に手が大きく写る画像は特に確認する。
- 人物の取り違え: B列に指定していない人物が主人公と同じ顔で描かれていないか、同席者が別人になっていないか。
- 端末の向き: スマホ・PC・タブレットの背面に、画像・グラフ・文字が描かれていないか。
- 利用と変化: 説明される対象が絵にあり、実際の掲載幅で必要な商品名・操作・作例を判別できるか。画面を紹介する場面で人物が大きすぎないか。変化が見分けられるか。未指定の実績や効果を絵で補っていないか。
- 参考素材: 指定箇所に反映されたか、保持すべき形・色・文字が合うか、別作品の内容が混入していないか。
- 演出: 主役と感情の強弱が伝わり、装飾・文字・内部コマ数が判断材料を隠していないか。

問題は画像・版・問題箇所・修正目的を短く記録する。機械的な本文照合は保存データの検証であり、画像内の文字一致の証明とは区別する。

「文字・人物・参考素材が正しい」と「前後を通して感情が動き、商品が分かり、次を読みたくなる」を分けて確認する。全画像を見たことだけで後者を合格にしない。短いD列の品質は実画像で確かめ、ネームの形式検証だけで保証しない。

## 修正と完成確認

絵だけの問題は該当画像の限定修正を優先し、変更対象と保持する文字・人物・構図を具体的に指示する。元画像と修正版を区別し、前後の画像と照合する。修正に伴う別の変化も確認する。承認済み台詞を修正の都合で書き換えない。脚本変更が必要なら差分と理由を提示する。文字は絵と一体生成し、後合成しない。

同じ問題が続く場合は、不足する設定・参照の不一致・一枚に含めた情報量を見直す。解決条件が変わらないまま再生成を繰り返さず、残る問題と必要な情報・選択肢を返す。

完成時は、全対象画像の成功と選択状態、番号・順序・欠落、修正が採用版へ反映されたことを確認する。書き出した場合はファイル件数・整合性と修正後の版を照合する。原画像や本文の掲載ブロックがある記事はその実施範囲も報告し、漫画画像だけの完成を記事全体の完成と取り違えない。自動選択、AIの確認、人間の受入、広告成果を別々に記録する。

混在記事への引き渡しでは、採用素材・版と掲載位置の対応、本文・実画面に任せた未制作部分を明記する。再掲した各位置で前後とのつながりを確認するが、同一素材を別の生成成果として数えない。
